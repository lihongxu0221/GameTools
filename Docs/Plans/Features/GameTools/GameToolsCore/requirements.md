# GameTools 需求规格说明书

## 1. 业务与运行环境
- **开发框架**：多目标 `net8.0-windows;net48`；契约层 `GameTools.Core` 为 `netstandard2.0`。兼容依据见 `plan.md` 与 `toolchain-compatibility.md`。
- **目标操作系统**：Windows 7 SP1 及更高版本（Win7 / Win8 / Win8.1 / Win10 / Win11）。
- **工具链**：Visual Studio 2022 17.8 起、.NET SDK 8.0.100 起、NuGet 6.2 起；解决方案使用经典 `GameTools.sln` 格式。
- **运行环境前置条件**：
  - Windows 7 必须安装 SP1 补丁。
  - 必须安装 Microsoft Visual C++ 2015-2022 Redistributable (Universal C Runtime, api-ms-win-crt-*)。
  - 建议安装 KB2533623 或 KB3063858、SHA-2 补丁（KB4474419/KB4490628）。
- **旧系统交付形态**：`net48` 目标不支持单文件发布与 ReadyToRun，走自包含部署。

## 2. 功能性需求

### 2.1 后台进程 (Background Process)
- **REQ-BG-01**：支持作为无界面后台守护进程常驻运行，支持可选系统托盘驻留模式（`--tray`）与纯无头模式（`--headless`）。
- **REQ-BG-02**：具备 Win32 消息泵机制（Message Pump），能够持续稳定接收分发系统消息（如 WM_HOTKEY）。同步调度须具备超时与取消能力。
- **REQ-BG-03**：支持跨进程单实例互斥（Single Instance），避免多开冲突。
- **REQ-BG-04**：支持优雅启动、运行中配置变更与平稳退出清理。

### 2.2 屏幕与窗口截图 (Screenshot)
- **REQ-CAP-01**：支持抓取全屏（包含多显示器虚拟桌面）与自定义矩形区域。
- **REQ-CAP-02**：支持抓取指定窗口句柄（HWND）画面。
- **REQ-CAP-03**：支持后台窗口截图（无需窗口前置激活）。按版本选择 `PrintWindow` 标志位（Windows 8.1 及以上优先 `PW_RENDERFULLCONTENT`）；调用失败或返回全黑内容时降级。
- **REQ-CAP-04**：严格保证 GDI DC 与 Bitmap 句柄即时释放，长周期高频截图无资源泄漏。
- **REQ-CAP-05**：支持输出为平台无关像素帧、BGRA 原始像素、PNG 字节数组及直接保存本地文件。

### 2.3 全局快捷键 (Global Hotkeys)
- **REQ-HK-01**：支持注册与注销任意系统级全局快捷键（Ctrl / Alt / Shift / Win 任意组合 + 键码）。
- **REQ-HK-02**：支持快捷键被系统或其他进程占用时的冲突检测，返回明确诊断异常；须区分「本进程重复注册」与「被外部占用」。
- **REQ-HK-03**：触发快捷键时采用线程池异步派发事件，不得阻塞底层 Win32 消息派发线程。

### 2.4 模拟文本与按键输入 (Text Input & Keystroke Simulation)
- **REQ-INP-01 (前台模式)**：基于 `SendInput` 实现，支持直接投递 Unicode 字符串（包括中文、Emoji、特殊字符），不受输入法状态干扰。非 BMP 字符须按 UTF-16 代理对成组投递，组内不得插入延迟。
- **REQ-INP-02 (前台按键)**：支持模拟常用控制键（Enter、Tab、Esc、Backspace、方向键）及修饰组合键；修饰键须在异常路径下补偿释放。
- **REQ-INP-03 (输入节奏)**：支持配置字符间模拟延时与随机抖动，贴合人类输入节奏；支持取消。
- **REQ-INP-04 (后台定向模式)**：支持针对目标非激活窗口直接投递 `WM_CHAR` / `WM_KEYDOWN` / `WM_KEYUP` 消息，且键消息参数须符合 Win32 约定（重复次数、按下状态位、扩展键标志）。
- **REQ-INP-05 (控件文本)**：支持针对标准 Windows 文本编辑控件发送 `WM_SETTEXT` 快速写入；跨进程调用须具备超时。

### 2.5 钩子监听进程消息 (Hooks & Process Monitoring)
- **REQ-HKP-01 (低级输入监听)**：基于 `WH_KEYBOARD_LL` 与 `WH_MOUSE_LL` 实现免注入的全局键盘与鼠标监听；安装与卸载须在消息泵线程执行。
- **REQ-HKP-02 (进程过滤)**：支持根据前台活动窗口的所属进程 ID / 进程名过滤，仅监控针对目标进程的用户交互；键盘与鼠标的目标须相互独立。
- **REQ-HKP-03 (防回收与零阻塞)**：回调委托必须显式通过强引用与 `GCHandle` 保护，杜绝 GC 回收；回调内仅做结构体读取与有界队列写入，不做任何阻塞操作。
- **REQ-HKP-04 (进程窗口事件监听)**：基于 `SetWinEventHook` 纯托管实现对指定目标进程的窗口创建、激活、移动与销毁事件监听；目标 PID 须校验，事件元数据须完整。

## 3. 验证范围声明

### 3.1 已验证范围
Windows 10 及以上（SDK 10.0.401 与 8.0.420）、`net8.0-windows` 与 `net48` 双目标的编译与自动化测试（各 75 项，全部通过）。

### 3.2 未验证范围
**Windows 7 SP1 / Windows 8 / Windows 8.1 未在真机运行。** 旧系统兼容性结论基于官方支持矩阵与特性探测设计，**不构成实机验证结论**。

以下场景亦未验证：真实 Unicode 输入端到端（含 Emoji 代理对）、硬件加速窗口截图与全黑降级、GDI 句柄耐久曲线、待机 CPU 占用、WPF 界面交互、非管理员运行与 UIPI 受限场景。

### 3.3 补偿手段
以 `IOsVersionProvider` 注入方式在单元测试中覆盖 Win7/8/8.1/10/11 全部版本分支，使截图降级策略等版本相关逻辑可在当前环境完整验证。

### 3.4 待需求方确认的验收阈值
见 `plan.md` 第 7.2 节：待机 CPU 计量口径、截图耗时基线、长周期测试规模、零阻塞耗时预算、非管理员运行下的期望结果。以上阈值未确认前，不得宣称性能与可靠性已达标。

## 4. 非功能性需求
- **稳定性**：CPU 待机占用低于 0.1%（阈值待确认），异常路径具备恢复与保护机制；同步调用不得永久阻塞。
- **兼容性**：Win7 SP1 ~ Win11 行为一致或具备平滑回退；双目标产物行为一致性纳入验收。
- **安全性**：无敏感数据泄漏，支持非管理员账户安全运行（UIPI 受限场景的期望结果待确认）。
- **可观测性**：关键路径输出结构化日志至滚动文件，单文件 5MB、保留 10 个历史文件；库层 Trace 输出须桥接至统一日志。
