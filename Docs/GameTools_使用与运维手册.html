快速开始与运行指南#

GameTools 提供开箱即用的命令行与托盘一体化宿主程序，可直接用于自动化测试、功能验证与现场诊断。

1. 编译构建

PowerShell 编译与测试命令
# 1. 还原并构建整个解决方案 (Release 模式)
dotnet build GameTools.slnx -c Release

# 2. 运行全量单元测试套件
dotnet test GameTools.slnx -c Release

# 3. 启动交互式演示宿主
dotnet run --project src/GameTools.App/GameTools.App.csproj

2. 宿主程序交互菜单

启动 GameTools.App 后，主控制台呈现功能仪表盘：

序号 功能菜单 底层核心机制 说明

后台进程与 Win32 消息泵#

Windows 底层系统的全局热键（RegisterHotKey）、窗口级通信（WM_COPYDATA）以及低级钩子派发，强依赖一个运行在单线程单元（STA）上的标准 Win32 消息循环（Message Pump）。

1. 核心类结构

位于 GameTools.Infrastructure.Host 命名空间：

  • BackgroundMessagePump：专用 STA 线程驱动的后台隐藏消息窗口宿主，实现 IBackgroundMessagePump。
  • SingleInstanceLock：基于 Windows 命名 Mutex 的单实例防护组件。

2. 跨线程调用的 1408 陷阱与解决方案

⚠️ Win32 致命规则 (ERROR_WINDOW_OF_OTHER_THREAD = 1408)：
Windows 操作系统明确规定：RegisterHotKey(hWnd, ...) 与 UnregisterHotKey(hWnd, ...) 必须在创建该 hWnd 的同一个线程上调用！如果外部工作线程或线程池直接调用该 API，系统将直接返回失败，错误码为 1408。
BackgroundMessagePump 原生消息驱动调度设计
// 1. 投递自定义执行消息至专用 STA 线程
public T InvokeFunc<T>(Func<T> func)
{
    if (Thread.CurrentThread == _thread) return func();

    T result = default!;
    Exception? error = null;
    using var ev = new ManualResetEventSlim(false);

    // 将执行委托压入线程安全队列
    _actionQueue.Enqueue(() =>
    {
        try { result = func(); }
        catch (Exception ex) { error = ex; }
        finally { ev.Set(); }
    });

    // 唤醒后台 STA 线程的 WndProc 处理该委托
    User32.PostMessage(_window.Handle, NativeConstants.WM_EXECUTE_ACTION, IntPtr.Zero, IntPtr.Zero);
    ev.Wait();

    if (error != null)
    {
        ExceptionDispatchInfo.Capture(error).Throw();
    }
    return result;
}

屏幕与窗口截图系统 (GdiScreenCapture)#

提供高稳定性、毫秒级响应的 GDI 屏幕抓取方案，完全克服 Windows 7 平台对高版本渲染特性的不兼容缺陷。

1. 抓取方式对比

模式 核心 API 适用场景 Win7 兼容性
DesktopBitBlt User32.GetDC + Gdi32.BitBlt 全屏截图、多显示器拼接、指定矩形裁切 原生完整支持
PrintWindow User32.PrintWindow 后台非激活窗口、被遮挡窗口抓取 需动态区分标志位
DesktopCropFallback WindowHelper + BitBlt 目标窗口为 DirectX/硬件加速无重绘消息时回退 自动平滑降级

2. Windows 7 与 8.1+ 的 PrintWindow 标志位分流

GdiScreenCapture 动态降级核心代码
bool printed = false;

// 1. 若为 Windows 8.1 或更高系统，优先尝试 PW_RENDERFULLCONTENT (0x02)
if (OSVersionHelper.IsWindows81OrGreater)
{
    printed = User32.PrintWindow(hWnd, memDc.DangerousGetHandle(), NativeConstants.PW_RENDERFULLCONTENT);
}

// 2. 若在 Windows 7 上（不支持 0x02），或高版本系统下 0x02 调用失败，自动降级为默认 0
if (!printed)
{
    printed = User32.PrintWindow(hWnd, memDc.DangerousGetHandle(), NativeConstants.PW_DEFAULT);
}

3. GDI 句柄泄漏防护 (RAII)

Windows 单个进程默认 GDI 句柄上限为 10,000。高频截图必须严格保证资源释放。本系统封装了：

  • SafeGdiDcHandle：析构时自动触发 DeleteDC；
  • SafeWindowDcHandle：析构时自动触发 ReleaseDC(hWnd, hdc)；
  • SafeGdiObjectHandle：析构时自动触发 DeleteObject。

系统全局快捷键系统 (Win32HotkeyManager)#

基于底层 RegisterHotKey 构建，支持动态组合键绑定、占用冲突检测及零延迟异步回调响应。

1. API 使用范例

C# 热键注册代码示例
// 1. 获取消息泵驱动的热键管理器
using var pump = new BackgroundMessagePump();
pump.Start();

using var hotkeyManager = new Win32HotkeyManager(pump);

// 2. 注册 Ctrl + Alt + A 快捷键并附带专用回调
int hotkeyId = hotkeyManager.RegisterHotkey(
    Keys.A, 
    KeyModifiers.Control | KeyModifiers.Alt, 
    () =>
    {
        Console.WriteLine("快捷键 Ctrl + Alt + A 被触发！");
    });

// 3. 注销快捷键
hotkeyManager.UnregisterHotkey(hotkeyId);

2. 常见异常处理矩阵

Win32 错误码 错误名称 原因分析 框架应对处理
1409 ERROR_HOTKEY_ALREADY_REGISTERED 该热键已被其他第三方程序（如 QQ、微信）独占注册 抛出明确提示异常，注明冲突按键
1408 ERROR_WINDOW_OF_OTHER_THREAD 在非窗口所属线程调用了 RegisterHotKey 框架内置 InvokeFunc 自动重定向至 STA 宿主线程
1400 ERROR_INVALID_WINDOW_HANDLE 窗口句柄已被注销或未启动 启动等待保障屏障，确保 Handle 有效

文本与按键模拟输入 (WindowsInputSimulator)#

提供双模式输入机制：前台高保真 Unicode 文本注入与后台定向窗口消息投递。

1. 双模式选型对比

特性 前台模式 (SendInput) 后台模式 (PostMessage / SendMessage)
目标窗口状态 必须获得系统焦点（处于前台） 窗口可处于未激活或被遮挡状态
输入法影响 无影响 (KEYEVENTF_UNICODE) 无影响 (WM_CHAR)
中文字符支持 直接投递 Unicode 码，完全直通 直接投递 UTF-16 字符字面值
游戏控件兼容 极高（模拟物理驱动层） 中等（部分 DirectInput 独占游戏不响应 WM_CHAR）

2. 模拟输入代码范例

WindowsInputSimulator 代码范例
var simulator = new WindowsInputSimulator();

// 1. 前台模式：直接输入中文长文本（每个字符间隔 15ms，防止吞字）
simulator.SendText("你好，这是来自 GameTools 的自动化测试文本！🎉", delayBetweenCharsMs: 15);

// 2. 前台模式：模拟按下 Ctrl + V 粘贴组合键
simulator.SendKeyPress(Keys.V, KeyModifiers.Control);

// 3. 后台模式：向非激活目标窗口投递按键与字符
IntPtr targetHwnd = new IntPtr(0x123456);
simulator.PostTextToWindow(targetHwnd, "后台自动输入数据\r\n");

// 4. 后台模式：针对标准 Windows Edit/TextBox 快速赋值
simulator.SetWindowText(targetHwnd, "瞬间填充的全文内容");

钩子与进程消息监听系统#

实现无注入跨进程全局按键/鼠标监听，与目标进程级窗口生命周期状态捕获。

1. 低级输入钩子 (LowLevelHookManager)

⚡ 低级钩子两大约束与架构解法：
1. GC 回收委托崩溃：托管代码的委托若被 GC 回收，底层 C 回调将引发致命的 Access Violation。解法：使用 GCHandle.Alloc(proc, GCHandleType.Normal) 强行固化句柄。
2. 系统超时强行注销：Windows 对低级钩子设有看门狗（约 200~300ms）。回调函数内严禁阻塞。解法：内部只向 Channel<T> 管道写入事件并立即返回；独立的异步任务进行前台进程比对与外部事件派发。
LowLevelHookManager 零阻塞管道设计
private IntPtr KeyboardHookCallback(int nCode, IntPtr wParam, IntPtr lParam)
{
    if (nCode >= 0)
    {
        uint msg = (uint)wParam;
        var kbStruct = Marshal.PtrToStructure<KBDLLHOOKSTRUCT>(lParam);

        // 零阻塞推入无界内存通道
        _eventChannel.Writer.TryWrite(new RawInputEvent
        {
            IsKeyboard = true,
            Message = msg,
            VkCode = (int)kbStruct.VkCode,
            ScanCode = (int)kbStruct.ScanCode
        });
    }

    // 毫秒内立即放行下一个钩子
    return User32.CallNextHookEx(_hKeyboardHook, nCode, wParam, lParam);
}

2. 进程事件监听 (WinEventHookManager)

基于 SetWinEventHook（WINEVENT_OUTOFCONTEXT），可精准绑定指定目标进程 PID，监听窗口的生命周期事件：

  • EVENT_SYSTEM_FOREGROUND (0x0003)：目标窗口获得前台焦点；
  • EVENT_OBJECT_CREATE (0x8000) / EVENT_OBJECT_DESTROY (0x8001)：窗口创建与销毁；
  • EVENT_OBJECT_SHOW (0x8002) / EVENT_OBJECT_HIDE (0x8003)：窗口显隐切换。

实施总结与交付报告归档#

本章节内容与版本控制文档 Docs/GameToolsCore/implementation.md 保持一致。

核心技术突破与收获

  1. 彻底解决 Win32 RegisterHotKey 跨线程 1408 报错：通过在 STA 后台消息泵中内置自定义消息派遣队列，无缝重定向外部线程的热键注册操作。
  2. 零阻塞低级系统钩子：通过 System.Threading.Channels 将操作系统回调与耗时进程匹配逻辑完全解耦，确保系统永不强退钩子。
  3. Windows 7 到 Windows 11 的高韧性兼容降级：针对 PrintWindow 标志位与 DWM 隐形边框，自适应多代 Windows 系统。
