GameTools 使用与运维手册

版本 0.1.0 · 更新日期 2026-10-08 · 对应分支 lihongxu/gametools-multi-target

GameTools 是一套 Windows 桌面底层交互工具库与宿主应用

提供五大能力：后台常驻与消息泵、屏幕与窗口截图、全局快捷键、前后台文本与按键模拟、全局输入钩子与跨进程窗口事件监听。库层为纯 .NET 实现，通过 P/Invoke 调用 Win32 API，不依赖驱动或进程注入。

应用宿主基于 WPF + Prism + NLog，可在 Windows 7 SP1 至 Windows 11 上运行。

1. 快速开始

1.1 构建

dotnet build GameTools.sln -c Release

双目标（net8.0-windows 与 net48）会一并产出。测试：

dotnet test GameTools.sln -f net8.0-windows
dotnet test GameTools.sln -f net48

1.2 运行

# 交互模式（默认）
GameTools.App.exe

# 仅驻留托盘
GameTools.App.exe --tray

# 完全无界面后台
GameTools.App.exe --headless

未知参数不会改变行为，因此参数拼写错误不会导致意外进入后台模式。多模式同时声明时 --headless 优先。

3. 宿主模式

模式参数行为适用场景
交互无显示主窗口与托盘图标日常操作与调试
仅托盘--tray最小化到托盘，不占用任务栏长期后台驻留

三种模式均受单实例互斥保护：已有实例运行时，新实例会提示并退出，不会重复安装全局钩子。

4. 界面操作

主窗口左侧为功能面板（截图、快捷键、输入模拟、钩子监听、窗口事件五个页签），右侧为实时日志，底部为状态栏与退出按钮。左右面板之间有可拖拽分隔条，宽度范围为左侧 420~1200 像素、右侧不小于 280 像素。

页签主要控件说明
截图全屏截图、区域截图（X/Y/宽/高）、窗口下拉选择、刷新窗口截图自动保存到程序目录下的 Screenshots 文件夹
快捷键组合键复选框、按键下拉、动作文本、已注册列表动作文本填写命令名（见下表）
输入模拟文本框、字符间隔与抖动、按键与修饰键、目标窗口下拉、刷新窗口前台输入需先将焦点切到目标输入框
钩子监听键盘/鼠标开关、过滤 PID、进程下拉、刷新进程、事件流过滤 PID 留空表示监听全局
窗口事件目标进程下拉、刷新进程、开始/停止、事件流监听窗口创建、销毁、显示、隐藏、位置变化等

4.1 后台消息泵

全局快捷键、输入钩子与窗口事件三者都依赖一个独立后台线程上的 Win32 消息泵：RegisterHotKey 要求在创建窗口句柄的同一线程执行，SetWinEventHook 与 UnhookWinEvent 同样要求安装与卸载在同一线程。

该消息泵在主窗口创建时自动启动，日志中可见 后台消息泵已启动，消息窗口句柄: 0x...。若启动失败，程序会弹出提示说明，此时截图与输入模拟仍可正常使用，但上述三项功能不可用。

若日志中出现「消息泵尚未启动或窗口句柄无效」，说明消息泵未在运行，请重启程序后再试。

4.2 最小化窗口无法截图

窗口下拉列表中带 [已最小化] 标记的项无法用于截图。Windows 会把最小化窗口的矩形放置到 (-32000,-32000) 并压缩为 160x28 的图标矩形，此时窗口没有可截图的客户区，后台截图同样无法进行。

若对最小化窗口发起截图，程序会明确提示「目标窗口当前处于最小化状态」，而不会产出无效图片。请先还原该窗口（点击任务栏图标或按 Win+↑），再重新选择并截图。

4.3 刷新列表与定位目标

窗口与进程列表在程序启动时枚举一次，目标程序在此之后新开或新启动时不会自动出现，需要手动刷新：

  • 刷新窗口：重新枚举当前可见窗口，用于「截图」与「输入模拟」页签的目标窗口下拉框。
  • 刷新进程：重新枚举当前进程，用于「钩子监听」与「窗口事件」页签的进程下拉框。

刷新会尽量保留当前选中项（按窗口句柄与进程 ID 匹配）；若原目标已关闭或已退出，选中项会回落为空，需重新选择。

进程列表中标记 [无窗口] 的条目为控制台程序或后台服务，这类进程同样可以作为钩子目标。列表较长时可直接在弹出列表内滚动，或用键盘输入名称前缀快速定位；窗口标题过长时列表内以省略号截断，悬停可查看完整标题。

4.1 快捷键动作命令

注册快捷键时需在动作文本框填写命令名，当前支持：

  • capture / screenshot：触发截图
  • hook / hooks：切换钩子监听
  • quit / exit：退出程序

填写其他内容会返回「未知命令」提示，不会注册。

4.2 输入校验

界面对数值输入做了范围保护，避免误填导致长时间无响应：

  • 区域宽高必须大于 0 且不超过 20000
  • 延时间隔与抖动不能为负数，超过 5000 毫秒按 5000 处理
  • 过滤进程 ID 必须为正整数

5. 截图

5.1 三种模式

  • 全屏：可选包含全部显示器（虚拟桌面）或仅主屏
  • 区域：按屏幕坐标抓取，支持负坐标（副屏位于主屏左侧）
  • 窗口：后台抓取指定窗口，无需前置激活

5.2 窗口截图的降级行为

窗口截图按标志位序列尝试，任一步成功即接受：

  1. Windows 8.1 及以上先试 PW_RENDERFULLCONTENT，可正确捕获硬件加速与 DWM 渲染内容
  2. 失败或内容全黑时退回 PW_DEFAULT
  3. 仍失败则试 PW_CLIENTONLY（仅客户区）
  4. 全部失败时，若窗口可见且未最小化，可回退到桌面裁剪
关于桌面裁剪回退

桌面裁剪抓取的是当前屏幕像素，被其他窗口遮挡的内容仍会被遮挡。因此它只能作为「拿到画面」的兜底，不能视为后台无遮挡截图。

5.3 输出格式

界面保存为 PNG。库层另提供两种输出：

  • CaptureWindowAsPng：PNG 字节数组
  • CaptureWindowAsBgra：BGRA 原始像素，紧密排列、每像素 4 字节、无行对齐填充

6. 全局快捷键

  • 支持 Ctrl / Alt / Shift / Win 任意组合，Win7 起建议勾选「不重复触发」
  • 占用诊断分两类：本进程重复注册（需先注销）与被系统或其他程序占用（需换组合）
  • 注册与注销均在独立消息线程完成，避免跨线程注册失败
  • 注销采用「先原生后状态」顺序：原生注销失败时保留记录以便重试

若注册返回 1408（目标窗口线程不一致），说明消息泵未就绪，请确认程序已完成启动。

7. 输入模拟

7.1 前台输入（SendInput）

  • 直接投递 Unicode 字符，不受输入法状态干扰，支持中文与符号
  • Emoji 与其他非 BMP 字符按 UTF-16 代理对成组投递，字符组内不插入延迟。若观察到 Emoji 显示为方框或替换字符，通常是目标应用不支持代理对序列，而非字符编码错误
  • 字符间隔与随机抖动可用于规避过快输入导致的丢字
  • 修饰键在异常路径下会补偿释放，避免按键粘连
UIPI 限制

当目标窗口的完整性级别高于本进程时，输入注入与消息投递会被 Windows 拦截。本项目以标准用户权限运行（不请求管理员），因此无法操作以管理员身份运行的窗口。遇到失败时界面会给出明确提示，不会静默失败。

7.2 后台输入（消息投递）

  • 文本通过 WM_CHAR 序列投递到指定窗口，窗口无需激活
  • 按键同时投递 WM_KEYDOWN、WM_CHAR、WM_KEYUP，并按 Win32 约定设置重复次数与按下状态位
  • 「替换窗口文本」使用 WM_SETTEXT 并带 2 秒超时，避免目标进程挂起时无限等待

后台投递依赖目标窗口的消息处理实现。自绘控件与非标准控件可能不响应，这是目标侧行为限制。

8. 钩子监听

8.1 低级输入钩子

  • 键盘与鼠标钩子可独立开关，过滤目标进程相互独立
  • 安装与卸载在消息线程完成，符合 Win32 对低级钩子的线程要求
  • 事件流上限 500 条，超出后丢弃最旧条目，长时间运行不会导致内存持续增长
  • 进程名结果按 PID 缓存，避免每个输入事件重复查询进程
钩子超时机制

低级钩子回调受 LowLevelHooksTimeout 限制（Windows 默认 3000 毫秒，超时会静默卸载钩子）。本实现将超时设为 1000 毫秒以便尽早暴露回调阻塞。回调路径仅做结构体读取与有界队列写入，不含任何阻塞操作。

8.2 窗口事件监听

  • 按事件类型白名单订阅（创建、销毁、显示、隐藏、重排、焦点、选中、改名、位置变化、前台切换、最小化起止）
  • 目标进程 ID 必须为正整数；传入 0 会被拒绝，因为原生语义中 0 表示监听整个桌面
  • 销毁类事件的窗口句柄可能已失效，此时以配置的目标进程 ID 回填元数据
  • 事件流上限 500 条

9. 日志

  • 输出位置：程序目录下的 logs 文件夹
  • 文件命名：gametools-日期.log，单文件上限 5MB，保留 10 个历史文件
  • 库层的 Trace 输出已桥接至统一日志，便于排查钩子与热键内部行为
  • 默认策略：Debug 构建启用，Release 构建可通过环境变量 GAMETOOLS_LOG 开启

日志滚动与总量上限避免长时间运行产生无界增长。

10. 故障排查

现象可能原因处理
启动即提示已有实例同名的 GameTools 进程仍在运行在任务管理器结束旧进程，或等待其自然退出
快捷键注册提示已被占用被系统或其他程序注册更换组合键，或关闭占用程序
快捷键提示已在当前进程注册本进程重复注册同一组合先在列表中注销，再重新注册
前台输入无反应焦点未在输入框；或目标窗口权限更高先点击目标输入框；确认目标未以管理员运行
后台投递无反应目标为自绘控件，未处理对应消息改用前台输入，或改用「替换窗口文本」针对标准编辑控件
窗口截图黑屏目标为硬件加速窗口且已尝试全部降级若目标可见，桌面裁剪回退可拿到画面，但可能含遮挡
钩子无事件未启用开关；或过滤了非目标进程确认开关状态；过滤 PID 留空以监听全局
窗口事件无回调目标进程 ID 无效；或监听期间目标未产生窗口变化确认 PID；切换到目标进程并创建/移动窗口
无头模式启动后「没反应」设计如此：无界面模式不创建窗口查看 logs 目录确认启动日志；按 Ctrl+C 退出
CPU 占用高于预期钩子与窗口事件同时开启且事件量大按需关闭；缩小过滤范围；观察日志中的事件速率

11. 能力边界

11.1 不支持

  • 不做进程注入与驱动级输入
  • 不拦截任意窗口消息（仅低级输入钩子与 WinEvent 公开事件）
  • 不做图像识别、OCR 与像素分析
  • 不提供跨平台支持（平台无关化仅为契约质量，不代表新增平台）

11.2 已验证与未验证

场景状态
Windows 10 及以上，双目标编译与自动化测试已验证（75 项测试全部通过）
Win7 / 8 / 8.1 真机运行未验证（无实机条件）
真实 Unicode 输入端到端（含 Emoji）未验证（需向第三方应用注入输入）
硬件加速窗口截图与全黑降级未验证（需特定图形驱动环境）
GDI 句柄耐久曲线未验证（需确认测量口径后长时间运行）
待机 CPU 占用小于 0.1%阈值待需求方确认计量口径
非管理员运行与 UIPI 受限场景期望结果待需求方确认

上表中未验证项不代表功能不可用，但也不构成已验证结论。相关缺口已记录在项目计划的验收标准章节。

13. 二次开发

在自有应用中引用 GameTools.Core、GameTools.Win32 与 GameTools.Infrastructure 三个工程即可使用全部能力，无需引入宿主应用。

13.1 最小使用示例

var pump = new BackgroundMessagePump();
pump.Start();

var hotkeys = new Win32HotkeyManager(pump);
int id = hotkeys.RegisterHotkey(VirtualKey.F8, KeyModifiers.Control | KeyModifiers.Shift, OnTrigger);

var capture = new GdiScreenCapture();
using CaptureResult result = capture.CaptureFullScreen(allMonitors: true);
// result.Frame 为平台无关的 BGRA 像素帧

hotkeys.Dispose();
pump.Dispose();

13.2 注意事项

  • 需先启动消息泵，热键与钩子的注册依赖其消息线程
  • 单实例互斥由宿主负责，库层不自动创建
  • 输入模拟与截图等耗时操作不应通过消息泵同步调度提交，会阻塞消息分发
